## 2) Rule for Current Wireframe Phase
Use the screenshots as the structural and content reference.

For this stage:
- Keep page section order closely aligned to current site unless a clear conversion issue is identified.
- Document all major section changes before introducing them in wireframes.
- Keep redesign choices traceable to trust and conversion objectives.

## 3) What Is In Scope For This Wireframe Cycle
- Structural wireframes (section hierarchy, CTA placements, content groupings).
- Trust and conversion sequence improvements.
- Dual-path intent support where applicable (Funding path and ISO path).

## 4) What Is Not In Scope For This Wireframe Cycle
- Production UI system and polished visual direction.
- Functional calculator implementation.
- Backend lead workflow implementation.

## 5) Change Annotation Standard
For every wireframe page, annotate changes using this label format:
- `KEEP`: Preserve existing section intent.
- `REFINE`: Keep section intent but improve structure/copy/CTA.
- `ADD`: New section introduced for trust or conversion.
- `MOVE`: Existing section repositioned in funnel order.
- `REMOVE`: Existing section removed with rationale.

## 6) Decision Filter for Changes
Only introduce structural changes if they improve at least one of:
- Trust clarity
- Conversion clarity
- CTA discoverability
- Audience-path clarity
